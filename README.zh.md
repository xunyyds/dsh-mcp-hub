# dsh-mcp-hub

**作者**: xunyyds

[English](README.md) | 中文

---

## 这是个啥？

一句话：**给 DSH 装一个管所有 MCP 服务器的控制台**。

测试连接、看工具清单、按工具开关、审批弹窗、配置备份，全在一个面板里干完。HTTP 服务器和本地 stdio 服务器一视同仁，不用为不同的传输写两套习惯。

它有个别人没有的东西：**MCP 工具的 schema 不再常驻提示词**。一台 207 个工具的服务器实测约 77 万字节（≈21 万 token），过去每一轮对话都要重新付一次这笔钱。装了这个插件，常驻的只有一个工具名，其余全部按需展开。

还有一条底线：**它不抢连接**。stdio 服务器和任何已经注册进 DSH 的服务器，都通过 `ctx.tools` 注册表代管，连接方始终是原生 `mcp-client`。面板只是读注册表，所以 stdio 服务器显示的是实时工具列表，而不是"不支持"。

## 🚀 装它

### 环境要求

| 项目 | 要求 |
|---|---|
| DSH | `>= 0.2.1-rc.2`（更低版本会在加载时按 `engines.dsh` 直接拒绝） |
| 审批通道 | 需要 `@deepseek-ai/dsh-user-approval`；没有时 `ask` 退化为拒绝（安全默认） |

### 安装步骤

1. **安装插件**

   ```sh
   dsh plugin --profile desktop add @dsh-external/dsh-mcp-hub
   ```

   从本地仓库装：

   ```sh
   dsh plugin --profile desktop add <本仓库路径>
   ```

2. **重启 DSH**

   装完必须重启，设置页才会出现 **MCP Hub**。服务端代码改动同理——面板里的「重连」只重拨 MCP 服务器，**不会重载插件代码**。

3. **添加服务器**

   点「新增」填 URL 或命令，或者直接用**快捷导入**：粘贴 `mcpServers` JSON、裸 URL、`cordis.patch.yml` 片段、`stdio` 条目任一格式，点「解析并回填表单」。解析**不写任何文件**，保存仍由你显式点击，所以贴错东西不会静默覆盖正在工作的服务器。

4. **使用功能**

   - **服务器**：连接测试、延迟、工具数、逐工具启用/禁用
   - **审批**：总开关 + 每服务器三态，默认跟随 DSH
   - **网关与目录**：调 `mcp_hub_tools` 的四个参数，预览与模型收到的逐字节一致
   - **本地服务器**：扫描各 profile 里已存在的 `mcp-client` 条目，一键接管进面板
   - **备份、导入与导出**：整份配置导出成一个 JSON，可跨机迁移
   - **调用日志**：按天记录每次调用的工具、参数、审批决策、耗时、成败

## 🪙 上下文预算：三层按需展开

这是本插件省 token 的核心，也是踩坑最多的一块。

系统提示词里常驻的只有 **`mcp_hub_tools` 一个工具名**，外加一段只列**服务器名与每台工具数**的目录。工具名和参数 schema 全部按层展开：

| 层 | 调用 | 返回 | 成本 |
|---|---|---|---|
| 1 | `mcp_hub_tools()` | 服务器名 + 每台工具数 | 与工具总数无关 |
| 2 | `mcp_hub_tools({ server: "windows" })` | 该服务器的工具名 + 一句话摘要 | 只付这一台 |
| 3 | `mcp_hub_tools({ names: ["mcp__windows__Screenshot"] })` | 这几个工具的完整参数 schema | 只付这几个 |

也可以随时用 `mcp_hub_tools({ query: "capture" })` 跨服务器按关键词检索，命中只回名字与摘要。

几条刻意的取舍，都是被现场问题教育出来的：

- **未命中不倒出全量工具名。** 早期实现 `query` 落空时会退回「列出全部工具名」，262 个工具时一次笔误吐 200 行——约等于命中 8 条的 25 倍，截断还会把整台服务器吃掉。现在未命中只回**服务器级摘要**，指向 `server=` 展开，成本与工具总数无关。

- **取回即揭示。** 摘掉 schema 只影响「模型看见什么」，执行仍按名字从注册表解析。但守规矩的模型不会调用不在 `tools` 数组里的工具——它会以为拿不到，然后**无限重复取回同一个名字**。所以现在 `names` 取回成功后，该工具下一轮会重新进入可调用列表（上限 32，按最旧淘汰）。

- **名字手误自动纠正。** `mcp_rea__open_binary` 这种下划线手误，旧文案只回一句「可能名字不对」，模型无从反推差异，只能原地重试。现在归一化后若目录里唯一匹配就直接纠正并说明；不唯一时列出最接近的真名。

- **零参数标注宁可漏标不可错标。** 第二层会把确证无参数的工具标成「无参数，可直接调用」，省掉一次 `names` 往返。判据是三条同时成立：`type:"object"` 确证 + `properties` 为空 + 无 `required`。注册表对部分工具是渐进补全 schema 的，只看 `properties` 为空会把**有必填参数的工具**也标成无参数，照标跳过取回反而换来一次校验失败。

- **超胖 schema 自动降级。** 单个 schema 超过约 16 KB 会降级成「参数名 + 类型 + 必需项」的浅视图，且**必需参数优先保留、先丢可选参数**——丢必需参数会让调用注定失败。

- **离线服务器如实说明。** 运行时上下文可能列 5 台、检索池只有 3 台，差集不是错误，是那两台连不上。`mcp_hub_tools` 会连同原因（如 `qfun：fetch failed`）一起报出来，免得模型以为那两台的工具有别的问题。

- **元工具不占检索位。** 上游那种「列出更多工具」的开关（如 `get_more_tools`）不进检索池——列进来只会让模型在本插件的两层目录与服务器自己的目录之间反复横跳。它仍可被显式调用。

**只有 `off` 档位会关掉一台服务器。** `full` 与 `lazy` 现在等价，都是「按需展开」；保留 `full` 这个名字只为兼容既有配置。整台禁用、逐工具禁用、`off` 档位三者共用同一份 `blockReason`：既从提示词消失，也拒绝执行、不能被检索取回——不会出现「面板说禁用、模型却还能叫」。

### 能力摘要：不写一行 prompt，新加服务器自己长出来

目录里每台服务器后面那串特征词是**从工具元数据现算的**，不是手写文案：

```
服务器：mobile（33 个工具）：日志·剪贴板·点击·崩溃·截图、rea（7 个工具）：函数·二进制·符号·反汇编·对比
```

这条区别是整个设计的支点。手写路由文案（「mobile 用来操作手机，rea 用来分析二进制」）会在两件事上腐烂：工具变多了、或者新接一台服务器，文案不会跟着变，于是模型**想不起来**还有那台机器。特征词不一样，它由三段统计直接推出来：

1. **分词**：工具名 snake_case 拆词、摘要全句、参数名递归三层，中英混合
2. **去通用词**：按「出现在 80% 以上服务器里」判定（不是硬编码黑名单——黑名单会随新服务器过期），再叠加词位判据：`动词_宾语` 的命名约定里首词是动词槽、末词才是能力本身，于是 `list` / `get` / `open` 被压到底，`install` / `click` / `swipe` 浮上来
3. **中英桥接**：`screenshot→截图`、`crash→崩溃`、`logcat→日志`，让英文工具名也能生成中文摘要

每台一行 15–20 token，超过 8 台服务器自动压缩成「分组摘要 + 一句检索指引」。索引按 `签名哈希` 缓存成 `storages/mcp-hub/capability-index.json`：**签名没变就用磁盘那份，变了才重建，读坏了就当场重算**——三层回退都不抛错，旧索引能用就不阻塞启动。

面板「网关与目录」里可以关掉它（少那串词，目录本身照旧）。

### 检索：BM25 + 能力词加权，中文查询不再是零命中

`mcp_hub_tools({ query })` 的排序内核经历过一次重写，起因是一个实测出来的事故：

```
旧实现 tokenize("反汇编 so 符号 调试") → ["so"]        ← 中文被 /[^a-z0-9]+/ 全切掉
旧实现 top1 → compare_source_to_bundle                 ← 只在描述散文里撞上了 "so"
```

中文全丢之后，能排到前面的只剩「描述里恰好带某个子串」的小众工具。现在：

- **CJK 切 2-gram**，中英混合查询都产出有意义的词项；`tokenize` 的签名与返回类型不变（严格超集，英文词一个不少）
- **BM25 打分**，idf 每次从当前目录现算；字段权重 名字 3 > 参数 1.2 > 摘要 1
- **能力词加成**：命中「工具名里的能力词」额外 1.5 倍，且加成只认工具名——摘要里顺带一提的散文词不再能挤到前面
- **双向中英桥接**：`崩溃→crash` 与 `crash→崩溃` 都通

改完的实测：`反汇编 so 符号 调试` 的 top3 全落在 rea；`进游戏卡死了拿崩溃栈` 的 top1 是 `mobile_get_crash`。

### JIT 触发提示：在正确的当口补一句话

目录解决的是「模型知道我有哪些服务器」，但「此刻该想起哪一台」是另一件事。真实事故：某轮任务里模型动了 40MB 的 `libil2cpp.so`、跑了几十次 `adb`、扒了 `tombstone`，而 `mobile_get_crash` 一次都没被想到——信号全在眼前，缺的是把信号接到工具上的那一跳。

打开后（**默认关闭**），每轮从「用户最近的话 + 最近几条命令/路径」里抽信号，命中某台服务器的触发词就补一行：

```
提示：mobile 有 33 个日志/截图类工具，可用 mcp_hub_tools(query="日志") 查看
```

它最大的风险是变成噪音，所以节流写得很硬：

- **每轮最多 1 条**、**每会话每台服务器最多 1 次**、**每会话总计不超过上限**（默认 3）
- 同一段信号文本不重复提示（否则同一句话会被换台服务器再复读一遍）
- **你说「找不到工具 / no such tool」时解除上述限制**——那句话的语义本来就是「再告诉我一遍」，但仍保留每轮 1 条，避免一次卡住就刷屏
- 状态按会话隔离，`also` / `so that` 里的 `so` 绝不触发（`so` 只认文件扩展名）

注入走官方 `ctx.systemPrompt.context()`（与工作目录、沙箱策略同一层，每轮重算），不自己拼 user message。还有一个必须跳掉的坑：**运行时上下文快照不能被当成下一轮信号读回来**，否则一条提示写进上下文后自己就成了信号，提示会自我续命——集成测试里专门钉了这条。

### 网关参数

**网关与目录** 页可调 `mcp_hub_tools` 的四个参数，保存即生效（每次执行现读配置，无需重启）：

| 参数 | 默认 | 范围 | 作用 |
|---|---|---|---|
| `searchLimit` | 8 | 1–20 | 单次检索最多返回几条命中 |
| `catalogLimit` | 200 | 1–500 | 取回全部失败时列出的可用工具名条数 |
| `schemaMaxBytes` | 16000 | 2000–128000 | 单个 schema 取回的字节预算，超了自动降级 |
| `loadBatchMax` | 12 | 1–50 | 一次 `names` 最多取回几个工具 |

另有三个**目录与提示**开关：

| 开关 | 默认 | 作用 |
|---|---|---|
| `catalog.capabilities` | 开 | 是否在服务器名后面挂自动生成的特征词 |
| `hint.enabled` | **关** | JIT 触发提示总开关 |
| `hint.maxTotal` / `hint.maxPerServer` | 3 / 1 | 每会话总提示上限 / 每台服务器上限 |

参数随整插件备份一起导出/还原（`gateway` / `catalog` / `hint` 字段）；旧备份没有这些字段时，合并保留本机现值、覆盖回到默认值。

## ✅ 审批

**审批** 页有一个总开关，以及每台服务器的三态覆盖。默认是**跟随 DSH**。

**跟随不是模仿，是直接消费官方**：同一个 `ctx.approval`、同一套 `ask` / `never` 折叠、同一个审批面板、同一份 `allowed-once` / `rejected` / `cancelled` / `unavailable` 结果词表。面板上显示的「部署默认策略」与「当前权限预设」读的也是官方服务的真实值，不是本插件重新推导的。

审批卡片三个按钮：

| 按钮 | 作用 |
|---|---|
| 拒绝 | 本次调用不执行 |
| 允许一次 | 只放行这次，下次仍会询问 |
| 本对话内允许 | 放行这次并记住该工具，本对话内不再询问 |

「本对话内允许」是一次点击：先写授权、再放行。换对话或重启 DSH 即失效——授权记在会话上，不写进配置，所以不会在你下次开新对话时静默免询问。审批页会列出当前会话授权并提供「清空本次授权」。

粒度是**工具**而不是服务器：批准 `send_msg` 不会顺带放行同服务器的 `get_skey`。按服务器记忆会让一次对只读工具的批准解锁整台服务器的全部能力，而你弹窗里看到的只是那一个动作。

**审批结果会告诉模型。** 审批发生在 UI，模型侧本来完全看不见——它无法区分「用户点了允许一次」和「这工具本来免审批」。现在每次审批过的调用，结果正文末尾会带回执，按用户实际点的按钮区分：

```
[审批：本次已由用户允许一次（下次仍会询问）]
[审批：本次已允许，并记住该工具，本对话内下次不再询问]
```

第一条对应「允许一次」；第二条对应「本对话内允许」。本对话内已有授权、这次没再弹窗时，回执是 `[审批：本对话内已授权，本次未再次询问]`。

**读不到策略就拒绝。** 没组合 `@deepseek-ai/dsh-user-approval`、或官方请求自身失败时，按 fail closed 拒绝，并在错误信息与日志里说明原因，不静默放行。

这张卡片只接管 `mcp__` 前缀的审批，其他审批仍走官方面板。它是运行时注册的 slot，卸载插件即恢复原状，**不修改任何 DSH 文件**。

## 📦 接管、备份与日志

**本地服务器** 卡片扫描每个 DSH profile 里的 `mcp-client` 条目（含 profile 根目录和各已装插件的 bundle 补丁），点「接管到面板」即可设置门禁、查看状态，无需重填 URL、命令或 Token。接管不改变连接的任何细节，它只是一条记录，不是重连。

**备份、导入与导出** 导出一个 JSON，含服务器列表、全部逐工具策略、审批总开关、网关参数、当前加载补丁：

```json
{
  "kind": "dsh-mcp-hub/backup",
  "version": 1,
  "exportedAt": "2026-10-20T03:14:15.000Z",
  "profile": "",
  "approval": { "followDsh": true },
  "servers": [ { "name": "qfun", "transport": "streamable-http", "url": "…", "approvalMode": "inherit", "tools": { "send_msg": { "approval": true } } } ],
  "patch": "…"
}
```

- **合并** 保留现有服务器，同名覆盖；**覆盖** 先清空列表，用于精确复刻一台机器。
- 导入前校验：`kind` 不对、`version` 不支持、服务器重名，写入前就被拒。
- 旧备份没有 `approval` 字段时，合并保留本机现值、覆盖回到「跟随」——「没写」不等于「关掉」。
- 调用日志刻意排除在外：它是按天追加的流水，塞进备份只会让文件无限增长。

⚠️ **备份里的 Token 是明文。它是凭证文件，不是可分享的产物。**

**调用日志** 按天记录每次调用的工具、参数、审批决策、耗时、成败与错误原文。`ok` 字段如实反映**最终结局**——包括本插件自己把调用弄失败的情况，不会出现「日志一片绿、实际全报错」。

## 🔌 HTTP API

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/mcp-hub/status` | 每服务器状态、托管标志、工具数（12 秒轮询，不含凭证） |
| GET/POST/PUT/DELETE | `/mcp-hub/servers` | 列出、新增或更新、删除 |
| GET | `/mcp-hub/test` | 连接并返回延迟、服务器信息、工具名 |
| GET | `/mcp-hub/tools` | 带策略的工具清单；`source` 标明 `registry` 或 `dial` |
| POST | `/mcp-hub/tool-policy` | 批量更新启用 / 审批 |
| GET/POST | `/mcp-hub/budget` | 读投放档位与桥接工具名，写单台或全部档位 |
| GET/POST | `/mcp-hub/gateway` | 读/写检索网关参数与工具目录，预览与注入逐字节一致 |
| GET/POST | `/mcp-hub/approval` | 读总开关、每服务器三态与官方策略；写开关 / 模式，`action:"grant"` 记一条会话授权，`action:"revoke-grants"` 清空 |
| GET | `/mcp-hub/pending` | 按 `callId` 反查待审批的 MCP 工具 |
| POST | `/mcp-hub/invoke` | 经真实管线的调试调用 |
| GET/POST | `/mcp-hub/backup` | 导出，或按 `mode` 恢复 |
| GET/POST | `/mcp-hub/local` | 扫描可接管服务器，或接管其中一个 |
| GET/POST | `/mcp-hub/import` | 加载补丁状态，或写入 / 移除 |
| GET/DELETE | `/mcp-hub/records` | 按天查看调用历史 |

**凭证访问边界。** `/servers` 返回明文 Token（编辑器要填回输入框），`/backup` 与 `/import` 返回含 Token / Authorization 的全文。这三条**只对回环同源请求**给满内容：

- 请求 `Host` 必须是回环地址（`127.0.0.1` / `[::1]` / `localhost`）；
- 带 `Sec-Fetch-Site` 时必须是 `same-origin` / `none`（跨站页面被拒）；
- 带 `Origin` 时其主机也必须在回环上。

从局域网地址访问面板仍能正常管理服务器，只是拿不到已保存的凭证（`_token` 不返回、`credentialVisible: false`），`/backup` 与 `/import` 直接 403。这样即使 web 服务被改绑到局域网（例如 remote-web-ui 那类插件），**端口本身不再是"谁能读走密钥"的边界**。

## 🧠 实现说明

```
模型 ──tools──▶ DSH 工具管线
                     │
         tools/pre-execute  ◀── 允许 / 询问（本插件）
         ctx.tools.guard()  ◀── 单调拒绝（本插件）
                     │
     @deepseek-ai/dsh-mcp-client  ──▶ 外部 MCP 服务器
                     │
               ctx.tools.register()  ──▶ 注册表（本插件在此读取）
```

- **连接归属从不转移。** `mcp-client` 拥有每一条 stdio 连接和每个已注册服务器。面板读注册表而非另开连接。
- **策略分两层。** `tools/pre-execute` 决定允许 / 询问，是可扩展瀑布，后续监听器理论上能翻案；`ctx.tools.guard()` 在其之后运行且不可逆——面板里禁用的工具在这里被否决。
- **审批不代问。** 跟随模式下不返回 `{kind:'ask'}` 让 `dsh-tools` 代问，而是自己调 `ctx.approval.request()`，再按官方词表映射回 `allow` / `deny` / `cancel`。两个必要理由：不落入 `dsh-tools` 把 `ask` 一律当「沙箱升权」的解释（那会让 `never` 变成拒绝），以及只有拿到 `allowed-once` 结果，才能分清「允许一次」与「本对话内允许」并如实回执。审计仍是官方写的 `approval/asked` + `approval/decided` 配对。
- **调试调用走真实管线。** 面板调用经 `ctx.tools.execute()`，审批、超时、内容投影全部生效。调用携带 `parent` 标记被识别为子派发，从而不被 PTC 模式折叠。面板调试没有 agent，因此不受审批门禁拦截——点「运行」本身就是明确授权。
- **状态是推导的，绝不伪造。** `mcp-client` 不导出连接状态，面板统计该服务器前缀下的已注册工具数。零个工具意味着「未连接」，而不是「已连接但没工具」。
- **工具名与原生一致。** 始终是 `mcp__<serverName>__<rawName>`，所以会话历史与权限规则在重启后依然有效。

## ⚠️ 已知限制

- 审批依赖 DSH 的审批通道。没组合应答者时 `ask` 退化为拒绝，这是安全默认。
- 会话级授权在内存里，进程重启即失效。这是有意的：授权不该跨会话，也不该跨重启。
- **服务端代码改动不热更新。** 改完 `lib/*.js` 必须重启 DSH；面板的「重连」只重拨 MCP 服务器，不重载网关代码。
- **检索是词面匹配，不是语义检索。** 工具名里的词（`capture`、`screenshot`）命中率最高；纯概念查询（「那个能改文件的东西」）可能落空——此时回服务器级摘要，换词或 `server=` 展开即可。
- **「取回即揭示」的完整链路只对严格遵守 `tools` 数组的模型有意义。** 容忍列表外调用的模型看不出差别，因此它的实际收益要等前者出现才能终审。
