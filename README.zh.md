# dsh-mcp-hub

**作者**: xunyyds

[English](README.md) | 中文

---

## 这是个啥？

一句话：**给 DSH 装一个管所有 MCP 服务器的控制台**。

- 连接测试、工具清单、按工具启用/禁用、审批弹窗、配置备份，全在一个面板里完成。
- HTTP 服务器和本地 stdio 服务器一视同仁，不用为不同的传输方式准备两套习惯。
- 不抢连接：stdio 和已注册进 DSH 的服务器都通过 `ctx.tools` 注册表代管，连接方始终是原生 `mcp-client`，面板只读注册表。

它最大的不同：**MCP 工具的 schema 不再常驻提示词**。一台 207 个工具的服务器，schema 约 77 万字节（≈21 万 token），过去每一轮对话都要重新付一次；装了这个插件，常驻的只有 `mcp_hub_tools` 一个工具名，其余全部按需展开。

---

## ✨ 功能一览

| 能力 | 你能得到什么 |
|---|---|
| 服务器管理 | 增删改、连接测试、延迟与工具数、逐工具开关 |
| 按需加载 | 工具 schema 不常驻，按服务器 / 按工具取回，成本与工具总数无关 |
| 智能目录 | 服务器名后自动挂能力特征词，模型一眼知道每台能干什么 |
| 中英检索 | 用中文或英文关键词找工具，命中只回名字与摘要 |
| JIT 提示 | 可选：在合适的当口提醒模型该用哪台服务器，带严格节流 |
| 审批 | 跟随 DSH 官方审批，三个按钮，审批结果会回执给模型 |
| 快捷导入 | 粘贴 mcpServers JSON、URL 或 patch 片段即可回填表单 |
| 一键接管 | 扫描已存在的 mcp-client 条目，接管进面板统一管理 |
| 备份与恢复 | 整份配置导出成一个 JSON，可跨机迁移 |
| 调用日志 | 按天记录工具、参数、审批决策、耗时与成败 |

## 🚀 安装

### 环境要求

| 项目 | 要求 |
|---|---|
| DSH | `>= 0.2.1-rc.2`（更低版本会在加载时按 `engines.dsh` 直接拒绝） |
| 审批通道 | 需要 `@deepseek-ai/dsh-user-approval`；没有时 `ask` 退化为拒绝（安全默认） |

### 安装步骤

1. **安装插件**

   ```sh
   dsh plugin --profile desktop add @dsh-external/dsh-mcp-hub
   ```

   从本地仓库装：

   ```sh
   dsh plugin --profile desktop add <本仓库路径>
   ```

2. **重启 DSH**

   装完必须重启，设置页才会出现 **MCP Hub**。升级插件同理——面板里的「重连」只重拨 MCP 服务器，不会重载插件代码。

3. **添加服务器**

   点「新增」填 URL 或命令；也可以直接用**快捷导入**：粘贴 `mcpServers` JSON、裸 URL、`cordis.patch.yml` 片段或 `stdio` 条目，点「解析并回填表单」。解析不写任何文件，保存仍由你显式点击。

4. **开始使用**

   - **服务器**：连接测试、延迟、工具数、逐工具启用/禁用
   - **审批**：总开关 + 每服务器三态，默认跟随 DSH
   - **网关与目录**：调整 `mcp_hub_tools` 的参数，预览与模型收到的内容一致
   - **本地服务器**：扫描各 profile 里已有的 `mcp-client` 条目，一键接管
   - **备份、导入与导出**：整份配置导出成一个 JSON
   - **调用日志**：按天记录每次调用的工具、参数、审批决策、耗时与成败

## 🪙 上下文预算：三层按需展开

系统提示词里常驻的只有 **`mcp_hub_tools` 一个工具名**，外加一段只列**服务器名与每台工具数**的目录。工具名与参数 schema 按层展开：

| 层 | 调用 | 返回 | 成本 |
|---|---|---|---|
| 1 | `mcp_hub_tools()` | 服务器名 + 每台工具数 | 与工具总数无关 |
| 2 | `mcp_hub_tools({ server: "windows" })` | 该服务器的工具名 + 一句话摘要 | 只付这一台 |
| 3 | `mcp_hub_tools({ names: ["mcp__windows__Screenshot"] })` | 这几个工具的完整参数 schema | 只付这几个 |

也可以随时用 `mcp_hub_tools({ query: "capture" })` 跨服务器按关键词检索，命中只回名字与摘要。

几个需要知道的行为：

- **未命中不会再倒出全量工具名。** 检索落空时只回服务器级摘要，并提示用 `server=` 展开，成本不随工具总数增长。
- **取回即揭示。** `names` 取回成功后，该工具下一轮会重新进入可调用列表（上限 32，按最旧淘汰），不会出现「模型以为拿不到、于是无限重复取回」。
- **名字手误自动纠正。** 形如 `mcp_rea__open_binary` 的下划线手误，如果能唯一匹配目录里的真名，会直接纠正并说明；不唯一时列出最接近的几个真名。
- **零参数标注宁可漏标不可错标。** 只有同时满足 `type:"object"`、`properties` 为空、无 `required` 三个条件，才会标「无参数，可直接调用」。
- **超胖 schema 自动降级。** 单个 schema 超过约 16 KB 会降级成「参数名 + 类型 + 必需项」的浅视图，且必须参数优先保留。
- **离线服务器如实说明。** 连不上的服务器会连同原因（如 `qfun: fetch failed`）一起报出来，不会混进检索池。
- **元工具不占检索位。** 「列出更多工具」这类开关（如 `get_more_tools`）不进检索池，但仍可被显式调用。

**只有 `off` 档位会关掉一台服务器。** `full` 与 `lazy` 现在等价，都是「按需展开」；保留 `full` 这个名字只为兼容旧配置。整台禁用、逐工具禁用、`off` 档位三者共用同一份拦截原因：既从提示词消失，也拒绝执行、不能被检索取回。

### 智能目录

目录里每台服务器后面那串特征词是**从工具元数据自动生成的**，不是手写文案：

```
服务器：mobile（33 个工具）：日志·剪贴板·点击·崩溃·截图、rea（7 个工具）：函数·二进制·符号·反汇编·对比
```

好处很直接：新接一台服务器，摘要自己就长出来了，不需要有人记得去改提示词；工具变多时特征词也会跟着变，模型不会「想不起来还有那台机器」。

特征词来自工具名、描述和参数名的统计，并带中英桥接（`screenshot→截图`、`crash→崩溃`、`logcat→日志`）。每台一行约 15–20 token，超过 8 台服务器会自动压缩成「分组摘要 + 检索指引」。如果不需要，可以在**网关与目录**里关掉它。

### 中英检索

`mcp_hub_tools({ query })` 支持中文和英文关键词，也能中英混用。中文查询不会被丢掉：

- `反汇编 so 符号 调试` → top3 落在 `rea`
- `进游戏卡死了拿崩溃栈` → top1 是 `mobile_get_crash`

命中只返回工具名与一句话摘要，完整参数仍需 `names` 取回。

### JIT 触发提示（默认关闭）

目录解决「模型知道我有哪些服务器」，JIT 提示解决「此刻该想起哪一台」。

打开后，每轮会从「你最近说的话 + 最近几条命令/路径」里抽取信号，命中某台服务器的触发词就补一行：

```
提示：mobile 有 33 个日志/截图类工具，可用 mcp_hub_tools(query="日志") 查看
```

为了避免变成噪音，节流写得很硬：

- 每轮最多 1 条；每会话每台服务器最多 1 次；每会话总计不超过上限（默认 3）
- 同一段信号文本不会重复提示
- 你说「找不到工具 / no such tool」时会解除上述限制，但仍保留每轮 1 条
- 状态按会话隔离；`also` / `so that` 里的 `so` 不会触发

### 网关参数

**网关与目录** 页可调 `mcp_hub_tools` 的四个参数，保存后下一次请求生效（无需重启）：

| 参数 | 默认 | 范围 | 作用 |
|---|---|---|---|
| `searchLimit` | 8 | 1–20 | 单次检索最多返回几条命中 |
| `catalogLimit` | 200 | 1–500 | 取回全部失败时列出的可用工具名条数 |
| `schemaMaxBytes` | 16000 | 2000–128000 | 单个 schema 取回的字节预算，超了自动降级 |
| `loadBatchMax` | 12 | 1–50 | 一次 `names` 最多取回几个工具 |

另有三个**目录与提示**开关：

| 开关 | 默认 | 作用 |
|---|---|---|
| `catalog.capabilities` | 开 | 是否在服务器名后面挂自动生成的特征词 |
| `hint.enabled` | 关 | JIT 触发提示总开关 |
| `hint.maxTotal` / `hint.maxPerServer` | 3 / 1 | 每会话总提示上限 / 每台服务器上限 |

这些参数会随整插件备份一起导出/还原；旧备份没有这些字段时，合并保留本机现值、覆盖回到默认值。

## ✅ 审批

**审批** 页有一个总开关，以及每台服务器的三态覆盖。默认是**跟随 DSH**：同一个审批面板、同一套 `ask` / `never` 折叠、同一份官方结果词表。面板上显示的「部署默认策略」与「当前权限预设」也直接读官方服务的值。

审批卡片三个按钮：

| 按钮 | 作用 |
|---|---|
| 拒绝 | 本次调用不执行 |
| 允许一次 | 只放行这次，下次仍会询问 |
| 本对话内允许 | 放行这次并记住该工具，本对话内不再询问 |

「本对话内允许」是一次点击：先写授权、再放行。换对话或重启 DSH 即失效——授权记在会话上，不写进配置。审批页会列出当前会话授权，并提供「清空本次授权」。

粒度是**工具**而不是服务器：批准 `send_msg` 不会顺带放行同服务器的 `get_skey`。

**审批结果会告诉模型。** 每次审批过的调用，结果正文末尾会带回执，按你实际点的按钮区分：

```
[审批：本次已由用户允许一次（下次仍会询问）]
[审批：本次已允许，并记住该工具，本对话内下次不再询问]
```

第一条对应「允许一次」，第二条对应「本对话内允许」。本对话内已有授权、这次没再弹窗时，回执是 `[审批：本对话内已授权，本次未再次询问]`。

**读不到策略就拒绝。** 没组合 `@deepseek-ai/dsh-user-approval`、或官方请求自身失败时，按 fail closed 拒绝，并在错误信息与日志里说明原因，不静默放行。

这张卡片只接管 `mcp__` 前缀的审批，其他审批仍走官方面板。它是运行时注册的插槽，卸载插件即恢复原状，不修改任何 DSH 文件。

## 📦 接管、备份与日志

**本地服务器** 卡片会扫描每个 DSH profile 里的 `mcp-client` 条目（含 profile 根目录和各已装插件的补丁），点「接管到面板」即可纳管，无需重填 URL、命令或 Token。接管不改变连接，只是把它记进面板。

**备份、导入与导出** 会导出一个 JSON，含服务器列表、逐工具策略、审批总开关、网关参数和当前加载补丁：

```json
{
  "kind": "dsh-mcp-hub/backup",
  "version": 1,
  "exportedAt": "2026-10-20T03:14:15.000Z",
  "profile": "",
  "approval": { "followDsh": true },
  "servers": [ { "name": "qfun", "transport": "streamable-http", "url": "…", "approvalMode": "inherit", "tools": { "send_msg": { "approval": true } } } ],
  "patch": "…"
}
```

- **合并** 保留现有服务器，同名覆盖；**覆盖** 先清空列表，用于精确复刻一台机器。
- 导入前会校验：`kind` 不对、`version` 不支持、服务器重名，都会在写入前被拒。
- 旧备份没有 `approval` 字段时，合并保留本机现值，覆盖则回到「跟随」——「没写」不等于「关掉」。
- 调用日志刻意不放进备份：它是按天追加的流水，塞进去只会让文件无限增长。

⚠️ **备份里的 Token 是明文。它是凭证文件，不是可分享的产物。**

**调用日志** 按天记录每次调用的工具、参数、审批决策、耗时、成败与错误原文。`ok` 字段反映最终结局，包括插件自身造成的失败。

### 安全与凭证

`config.json`、`cordis.patch.yml` 和备份文件都可能含明文 Token，请勿提交或分享。只有在回环同源请求下，面板才会返回已保存的凭证；从局域网访问仍能正常管理服务器，但看不到 Token，备份与导入也会被拒绝（403）。

## ⚠️ 已知限制

- 审批依赖 DSH 的审批通道。没组合应答者时 `ask` 退化为拒绝，这是安全默认。
- 会话级授权在内存里，进程重启即失效。这是有意的：授权不该跨会话，也不该跨重启。
- **插件代码改动不热更新。** 升级或改完 `lib/*.js` 必须重启 DSH；面板的「重连」只重拨 MCP 服务器，不重载插件代码。
- **检索是词面匹配，不是语义检索。** 工具名里的词（`capture`、`screenshot`）命中率最高；纯概念查询（「那个能改文件的东西」）可能落空——此时回服务器级摘要，换词或用 `server=` 展开即可。
- **「取回即揭示」只对严格遵守 `tools` 数组的模型有实际收益。** 容忍列表外调用的模型看不出差别。
